## 1. 一个普通的对话需要什么
我们说正常一次普通的对话流程是什么样的呢，简单如下：
```
用户输入 → 模型回复 → 结束
```
这种简化单次模式需要 agent 能够很好的理解用户意图并生成相应回复，这其实是基础大语言模型的基本功能。但是拿到agent里，这里大模型和基础的又不太一样，agent中的大模型存在外挂模块，合在一起来回答用户问题，比如外挂一个工具。如果用户的问题需要涉及到某个工具才能完成，那么大模型就会自动执行某个工具，拿到工具结果后进行作答。

- **传统LLM**：用户输入 → LLM直接回复 → 结束
- **Agent模式**：用户输入 → LLM判断是否需要工具 → 执行工具 → LLM整合结果 → 最终回复

## 2. agent的大模型入口
由于我们项目基于claudecode教程改编而来，因此我们沿用claudecode的大模型入口函数，这也是后续所有需要请求大模型的时候的固定函数。
函数的主体框架为：
```python
response = client.messages.create(
    model=MODEL,          # 模型名称（必填）
    system=SYSTEM,        # 系统提示词/角色设定（可选）
    messages=state.messages,  # 对话历史消息列表（必填）
    tools=TOOLS,          # 工具/技能定义（如 readfile、浏览器控制）
    max_tokens=8000,      # 最大输出 Token 长度
)
```
 这是Claude 官方 SDK（anthropic-sdk-python） 的标准调用写法，里面有固定的标准参数，当填好参数后，大模型就能返回一个结果。

其中，
* MODEL我们可以使用便宜的如deepseek；
* SYSTEM为系统提示词，系统提示词可以很简单，也可以很复杂（复杂的提示词由多个部分组成，我们后续会讲）；
* messeges：为本次 / 历史+本次的用户输入；
* TOOLS：为传入的可用工具箱，这里是用户或者系统能发现的所有工具调用方法；从这个我们可以看到claude标准sdk讲工具默认为一个携带参数了。
* max_tokens：就是单次输出最大token量；

至于调用了这个函数后，sdk内部如何运实现的我们可以不用关注，大概的逻辑就是，大模型根据输入信息+工具说明+系统提示词设定，给出了最合理的回答。这个回答`response`也是结构化的内容后面说。

## 3. 关于工具tools
工具能力可以说是普通对话语言大模型能进化到agent的关键。工具相当于大模型的外接手脚，有了手脚能干的事情就非常多了，能实现的功能也更多。

说回到对该sdk使用的tools结构，其实比较固定大体2个步骤：步骤1需要写具体工具函数的实现逻辑；步骤2注册到工具箱里面给大模型看；

比如我们写一个读取本地文件的工具函数：
* 步骤一：比较简单，加载路径，读取内容，返回内容，普通的python实现：
```
# 给定一个路径，返回读取的内容（最大长度limit）
def run_read(path: str, limit: int = None) -> str:
    try:
        text = safe_path(path).read_text()
        lines = text.splitlines()
        if limit and limit < len(lines):
            lines = lines[:limit] + [f"... ({len(lines) - limit} more lines)"]
        return "\n".join(lines)[:50000]
    except Exception as e:
        return f"Error: {e}"
```
* 步骤二：注册到工具箱中，后续直接给大模型使用
工具模版定义如下：
```
TOOLS = [
    {
        "name": "工具名",
        "description": "工具作用",
        "input_schema": {
            "type": "object",
            "properties": {
                "参数1": {"type": "string", "description": "说明"},
                "参数2": {"type": "string", "description": "说明"}
            },
            "required": ["必填参数名"]
        }
    }
]
```
对应到本例：
```
TOOLS = [
    {
        "name": "read_file",
        "description": "读取指定路径的文件内容，支持限制读取行数",
        "input_schema": {
            "type": "object",
            "properties": {
                "path": {
                    "type": "string",
                    "description": "要读取的文件路径（绝对路径或相对路径）"
                },
                "limit": {
                    "type": "integer",
                    "description": "可选，限制读取的最大行数，不填则读取全部内容"
                }
            },
            "required": ["path"]
        }
    }
]
```
这就是大模型的参数tools的输入，read_file函数就是当大模型说要要使用这个工具的时候，我们就解析然后调用我们定义的run_read函数即可。

那么更多的工具就可以按照这种模版往TOOLS中添加，大模型就变成一个具备使用很多工具能力的大模型。

## 4. 关于大模型一次response返回
一次基本的大模型请求的参数都说完了，输入给大模型后就会返回一个结果。那么对于response的返回结果的格式也是固定的，大概长下面这样：
```
response = {
    "id": "msg_xxx",           # 消息唯一ID
    "type": "message",         # 固定为 message
    "role": "assistant",       # 固定为助手
    "content": [],             # 核心内容（文本/工具）
    "model": "claude-3-5-sonnet-20241022",
    "stop_reason": "",         # 结束原因：end_turn / tool_use
    "stop_sequence": None,
    "usage": {                 # token 消耗
        "input_tokens": 123,
        "output_tokens": 45
    }
}
```
需要重点关注输出的几块内容：
* stop_reason：详细说明本次返回的原因。当前包含2种：end_turn / tool_use；end_turn表示不需要工具调用，结束了；tool_use 表示本次需要工具调用才能得到结果，调用工具的详细信息在content中。
* content：这个是返回内容的关键。里面包括了普通回答，工具调用详细（注意：**只是返回要调用哪些工具，不包括执行具体的工具**）；
* 其他参数：比如记录token消耗，使用的模型等；

来个具体的，比如说我们使用上面的工具（仅读文件功能），读取一个文件内容，大模型的response可能就是：
```
Message(
    id='0a2f29fe-eba5-49a2-b053-095aade1c075',
    container=None,
    content=[
        TextBlock(
            citations=None,
            text='我来查看test.py文件的内容。',
            type='text'
        ),
        ToolUseBlock(
            id='call_00_dmd7uCge9eTER1itzxi3HXJv',
            caller=None,
            input={
                'path': 'test.py'
            },
            name='read_file',
            type='tool_use'
        )
    ],
    model='deepseek-chat',
    role='assistant',
    stop_details=None,
    stop_reason='tool_use',
    stop_sequence=None,
    type='message',
    usage=Usage(
        cache_creation=None,
        cache_creation_input_tokens=0,
        cache_read_input_tokens=512,
        inference_geo=None,
        input_tokens=10,
        output_tokens=50,
        server_tool_use=None,
        service_tier='standard'
    )
)
```
非常清晰的content包括2个回复块：
一个普通的文本块：回答了我们的问题说要查看内容；
另外一个工具调用块：说要调用TOOLS中的这个读函数；

大模型为什么能知道要调用这个函数呢：一是我们给的TOOLS中有详细功能说明，**这非常重要**，另外大模型根据我们输入和工具说明智能回答出可以调用工具，这是大模型大脑的固有能力。

## 5. 如何处理返回结果
有了大模型给我们的响应后，接下来就是代码框架里处理响应并拿到结果了。

这里涉及到对返回块和状态的解析，重点包括：
* stop_reason：这是一个很重要的状态判断，如果是工具调用（tool_use），那么后续处理就要执行工具调用。否则就认为对话结束了不用做什么。
* content：这个模块包含了所有要处理的内容，包括普通信息，包括工具调用的详细，里面可能一个或者多个block，需要依次循环处理。

那么一个简单的问答后解析结果就如下：
```
print(f">> 本轮输入内容：{state.messages}")
response = client.messages.create(
    model=MODEL,
    system=SYSTEM,
    messages=state.messages,
    tools=TOOLS,
    max_tokens=8000,
)
print(f">> 大模型响应的完整结果: {response}")

results = []
for block in response.content:
    print(f">> 大模型响应的块类型: {block.type}")
    if block.type == "text":
        print(f">> 大模型响应的块内容: {block.text}")
    elif block.type == "tool_use":
        pathfile = block.input["path"]
        print(f">> 大模型工具块中的路径: {pathfile}\033[0m")
        output = run_read(pathfile)
        print(f">> 工具执行后的输出:{output[:200]}")
        results.append({
            "type": "tool_result",
            "tool_use_id": block.id,
            "content": output,
        })
print(f"本轮结果:{results}")
```
我们给一个最朴素的system角色：
```
SYSTEM = (
    f"You are a helpful assistant at {os.getcwd()}. "
    "Provide clear and concise responses to user queries."
)
```
现在我主目录下有一个文本：text.py，我告诉大模型读取这个文件，那么命令后的输出就是：
