## 1. 什么是会话内的todo计划
我们经常能看到，有些大模型或者你和大模型说按照步骤解决问题的时候，大模型通常会列出计划，哪些做完了就画个勾，没做完就空着，当前正在执行的是哪一项。那么这个功能就是会话内的todolist做法。比如下面这个样子：

这一章先想成一个很简单的结构：

```
当前计划：
[x] 新建 hello_s03.py，内容为打印 'hello from s03' 的 main 函数
[>] 执行 python hello_s03.py，确认输出 (执行脚本)
[ ] 用 edit_file 将 'hello from s03' 改为 'hello, todo works!'
[ ] 再次运行，确认新输出
[ ] 执行 wc -l hello_s03.py 报告行数
```

那么学习这段教程可以发现，其实这里是以一个工具的方式来实现的。也就是说生成一个工具：比如说就叫todo 工具，当告诉agent希望以列计划的方式来解决某个问题的时候，agent会像调用其他工具一样来调用todo工具，列计划一步步执行。

那么这里的核心就包括2个：
* 对todo工具描述的足够准确，让agent能识别到并调用这个工具；
* todo里面的具体实现方法要准确，比如一次只执行一个待执行的项；

## 2. 列计划模式的好处
我们知道大模型受限于上下文的因素，注意力始终受上下文影响。如果没有一块显式、稳定、可反复更新的计划状态，大任务就很容易漂。所以让大模型一开始列好计划，然后后续一步步按照计划走，是一个可行的方案，避免任务一大就漂了。

因此可以让 agent 把当前会话里的计划外显出来，并且持续更新，每次也只做其中一项就会好的多，毕竟这样注意力更集中了。

## 3. 如何写这个工具函数

我们说些工具函数，一个是给大模型看的定义，大模型只有明白了定义才能找到这个工具。直接看教程中的定义：
```
    {
        "name": "todo",
        "description": "Rewrite the current session plan for multi-step work.",
        "input_schema": {
            "type": "object",
            "properties": {
                "items": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "content": {"type": "string"},
                            "status": {
                                "type": "string",
                                "enum": ["pending", "in_progress", "completed"],
                            },
                            "activeForm": {
                                "type": "string",
                                "description": "Optional present-continuous label.",
                            },
                        },
                        "required": ["content", "status"],
                    },
                },
            },
            "required": ["items"],
        },
    },
```
那么agent在看到这个todo后，就会生成一个按照这种结构的todo数组，且数组每项又是一个object，包含了`content `,`status `,`activeForm` 三个属性。有了agent生成的这个todolist后，后续的工具才能基于这个结构来写函数处理。（当然为什么是这三个属性，也是因为后续函数的定义是这样的，所以在给大模型看的工具定义上也定死了输入规范）。

解释下这三个意思：
- `content`：这一步要做什么，具体的描述内容。
- `status`：这一步现在处在什么状态，强制枚举值。
- `activeForm`：当它正在进行中时，可以用更自然的进行时描述。

## 4. 定义这个工具类与具体实现
下面就是如何具体实现工具方法了。为了实现一步步的处理任务的过程，那么这个工具的实现方法比其他工具就复杂一点，不再单纯只是一个函数就可以的。因为涉及到处理完一个计划后还要处理下一个计划，也就是始终需要维护一个对象状态，所以这个todo的工具实现就是一个完整对象的实现。结构如下：

实现细节放在后面，这里解释一下功能：
* `update `:最重要，实现当前多步计划中进行状态更新，完成一项划一项并执行下一项；
* `render `:打印出来当前的计划所有状态；

```
TOOL_HANDLERS = {"todo": lambda **kw: TODO.update(kw["items"])}
```
回到工具函数的调用，那么就应该包括一项很重要的调用，将items数组传入进行处理。

```
def agent_loop(messages: list) -> None:
    loopnum = 0
    while True:
        loopnum += 1
        print(f"\n新的一次循环{loopnum}")
        print(f"当前计划：{TODO.render()}")

        response = client.messages.create(
            model=MODEL,
            system=SYSTEM,
            messages=messages,
            tools=TOOLS,
            max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})

        print(f"当前大模型响应：{response.content}")

        if response.stop_reason != "tool_use":
            return

        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue

            handler = TOOL_HANDLERS.get(block.name)
            try:
                output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
            except Exception as exc:
                output = f"Error: {exc}"

            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": str(output),
            })
```

我们可以看到一步步过程，在最开始没有计划的时候，调用工具的时候大模型生成了一个结构化的计划，且附带前后顺序的计划。

有了计划以后，大模型开始一步步执行计划了，并在每执行完一个就标记一下状态（这个是在update中实现的），直到结束。

## 5. 附录update代码
```
def update(self, items: list) -> str:
        if len(items) > 12:
            raise ValueError("Keep the session plan short (max 12 items)")

        normalized = []
        in_progress_count = 0
        for index, raw_item in enumerate(items):
            content = str(raw_item.get("content", "")).strip()
            status = str(raw_item.get("status", "pending")).lower()
            active_form = str(raw_item.get("activeForm", "")).strip()

            if not content:
                raise ValueError(f"Item {index}: content required")
            if status not in {"pending", "in_progress", "completed"}:
                raise ValueError(f"Item {index}: invalid status '{status}'")
            if status == "in_progress":
                in_progress_count += 1

            normalized.append(PlanItem(
                content=content,
                status=status,
                active_form=active_form,
            ))

        if in_progress_count > 1:
            raise ValueError("Only one plan item can be in_progress")

        self.state.items = normalized
        self.state.rounds_since_update = 0
        return self.render()
```
