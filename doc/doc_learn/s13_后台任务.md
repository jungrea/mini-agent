# s13_后台任务

本节主要介绍一下后台任务，顾名思义后台任务就是将一个待执行任务放在后台去执行，而主流程可以继续做剩下的事情，之所以要这么做的原因是因为有些任务非常的耗时，同时其他的后续任务又不依赖于这个任务，这种时候就可以并行的处理，让耗时的任务到后台去执行，而不耗时的任务可以在主流程中继续执行，主流程中，只需要定时的去看一下后台的执行任务状态并保持随时合并到主任务就可以了。

## 1. 后台任务的架构

通过拆解后台任务想要实现的目标不难发现，后台任务至少要包含以下2点：
* 支持某个任务以子进程的方式在后台运行，子进程运行过程中不会干扰到主任务；
* 主线程能够捕获到已经完成的子进程，并将结果带到下一轮的对话中，以此提现对后台进程的响应。

流程图表示就是如下：

```
+==============================+      +==============================+
|      主线程 (Agent Loop)      |      |      后台线程 (Worker)         |
+==============================+      +==============================+
|  1. drain_notifications()     |     |  subprocess.run(command)     |
|              |                |     |              |               |
|              v                |     |              v               |
|  2. 注入 <background-results> |      |  捕获 stdout / stderr        |
|              |                |     |              |               |
|              v                |     |              v               |
|  3. LLM 调用                  |      |  判断状态: completed /        |
|              |                |     |     timeout / error          |
|              v                |     |              |               |
|  4. 解析 tool_use             |      |              v               |
|       +------------+          |     |  _persist_task() 写入 JSON    |
|       |            |          |     |              |               |
| bash/read_file  background_run ────>|              v               |
|                     |         |     |  notification_queue.push()   |
|                     v         |     +==============================+
|  5. 执行工具, 返回结果           |                |
|              |                |                | 通知入队
|              v                |                |
|        下一轮循环               |<────────────── +
+==============================+
```
后台进程的任务是以`subprocess.run(command) `,这是Python启动一个独立进程的语句，因为我们的项目是以Python来运行的。

## 2. 后台任务具体设计

### 2.1 与大模型的交互-工具系统
首先就是大模型如何触发，形成一个后台任务。上面的流程图已经给出来了，依然是以工具的形式来调起后台任务。这里就多说一句，大模型的工具系统不愧是手脚，确实太有用了，我们之前的很多功能基本上都是和工具相关。

既然是使用工具，那么我们依然是需要定义一个工具函数给大模型，同时有一个实现函数来具体实现。

```python
TOOLS = [
    {
        "name": "background_run",
        "description": "Run command in background thread. Returns task_id immediately.",
        "input_schema": {
            "type": "object",
            "properties": {
                "command": {
                    "type": "string"
                }
            },
            "required": [
                "command"
            ]
        }
    },
    {
        "name": "check_background",
        "description": "Check background task status. Omit task_id to list all.",
        "input_schema": {
            "type": "object",
            "properties": {
                "task_id": {
                    "type": "string"
                }
            }
        }
    }
]
```
* 第一个工具就是创建一个后台任务，并立马返回它的一个任务ID。这个任务ID可以作为主任务，后续每次循环的时候查一下这个ID是否被完成了来使用。
* 第二个工具就是检查一下后台任务，把所有的后台任务列举出来的意思。

### 2.2 后台任务的类

根据工具的大概意思，其实也是很容易设计出针对工具的类，无非就是如何启动一个后台任务、如何把后台任务ID传回去、如何检查当前所有的后台任务等等和后台任务相关的一些函数。

我们给出这个类的主要方法：

```python
# -- BackgroundManager: 线程执行 + 通知队列 --
class BackgroundManager:
    def __init__(self):
        self.dir = RUNTIME_DIR
        self.tasks = {}  # task_id -> {status, result, command, started_at}
        self._notification_queue = []  # 已完成任务的结果通知
        self._lock = threading.Lock()

    # ... 省略部分中间辅助函数

    def run(self, command: str) -> str:
        """启动后台线程，立即返回 task_id。"""
        task_id = str(uuid.uuid4())[:8]
        output_file = self._output_path(task_id)
        self.tasks[task_id] = {
            "id": task_id,
            "status": "running",
            "result": None,
            "command": command,
            "started_at": time.time(),
            "finished_at": None,
            "result_preview": "",
            "output_file": str(output_file.relative_to(WORKDIR)),
        }
        self._persist_task(task_id)
        thread = threading.Thread(
            target=self._execute, args=(task_id, command), daemon=True
        )
        thread.start()
        return (
            f"Background task {task_id} started: {command[:80]} "
            f"(output_file={output_file.relative_to(WORKDIR)})"
        )

    # ... 省略部分代码

    def check(self, task_id: str = None) -> str:
        """查看单个任务状态，或列出所有任务。"""
        if task_id:
            t = self.tasks.get(task_id)
            if not t:
                return f"Error: Unknown task {task_id}"
            visible = {
                "id": t["id"],
                "status": t["status"],
                "command": t["command"],
                "result_preview": t.get("result_preview", ""),
                "output_file": t.get("output_file", ""),
            }
            return json.dumps(visible, indent=2, ensure_ascii=False)
        lines = []
        for tid, t in self.tasks.items():
            lines.append(
                f"{tid}: [{t['status']}] {t['command'][:60]} "
                f"-> {t.get('result_preview') or '(running)'}"
            )
        return "\n".join(lines) if lines else "No background tasks."

    def drain_notifications(self) -> list:
        """返回所有已完成的任务，并清空所有待处理完成通知。"""
        with self._lock:
            notifs = list(self._notification_queue)
            self._notification_queue.clear()
        return notifs
```

这个类里面省去了一些中间函数，我们只关注比较核心的功能函数。在大模型调用的时候，主要就是调用这个类里面的核心功能函数。

另外一个特别的点就是，后台任务执行的结果是以结构化的方式存储在本地磁盘的，这样的好处就是后台任务执行完以后，结果不会因为会话窗口的关闭而丢失。

## 3. 看看主循环

主循环其实和普通章节的主循环差不多：有用户的问题，有大模型的请求，有工具的调用，有返回的结果，这样一轮轮的循环。唯一的不同就是，在一次新的循环过程中，我们需要把已经完成的后台任务的结果给拿出来，并作为新一轮的输入。

这里就体现后台类中的一个主要函数：`notifs = BG.drain_notifications()`

完整的主循环如下：

```
def agent_loop(messages: list):
    while True:
        # 排空后台通知，在下一次模型调用前作为合成的 user/assistant
        # 消息对注入
        notifs = BG.drain_notifications()
        if notifs and messages:
            notif_text = "\n".join(
                f"[bg:{n['task_id']}] {n['status']}: {n['preview']} "
                f"(output_file={n['output_file']})"
                for n in notifs
            )
            messages.append({"role": "user", "content": f"<background-results>\n{notif_text}\n</background-results>"})
        response = client.messages.create(
            model=MODEL, system=SYSTEM, messages=messages,
            tools=TOOLS, max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            return
        results = []
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)
                try:
                    output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
                except Exception as e:
                    output = f"Error: {e}"
                print(f"> {block.name}:")
                print(str(output)[:200])
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": str(output)})
        messages.append({"role": "user", "content": results})

```

那么通过这种方式，我们就实现了后台任务的启动、后台任务的后台执行、以及执行完之后任务结果的汇入主循环。
