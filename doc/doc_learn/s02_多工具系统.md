## 1. 多个工具函数如何使用
前面章节我们已经接触过了工具系统，我们说工具是大模型agent比较核心的地方，相当于大模型的手和脚，手脚有多好用决定了模型的能力高低。

之前每次接触的都是一种类型的工具函数，随着项目的扩大工具也会变得很多。比如比较常用的：

 一、文件操作工具（核心编码必备）
|工具名称|核心用途|
|---|---|
|Read|读取各类文件（文本、图片、PDF、Notebook），支持局部内容读取，无需完整打开文件。|
|Edit|精准编辑文件，支持行级替换、插入、删除，是写代码、改文件最常用的工具。|
|Write|新建文件或覆盖写入文件，适合从零创建代码文件、文档等。|
|Glob|按通配符匹配查找文件（如 `src/\*\*/\*\.ts`），快速定位目标文件。|
|Grep|搜索文件内容，支持关键词、正则表达式，返回匹配行及上下文，快速查找代码片段。|

二、命令执行工具（系统交互）

|工具名称|核心用途|
|---|---|
|Bash|执行 Linux/macOS 系统的 Shell 命令，支持交互模式，可捕获命令输出结果。|

三、Web搜索网络工具（外部信息获取）

|工具名称|核心用途|
|---|---|
|WebFetch|抓取网页内容，自动将 HTML 转换为文本或 Markdown，支持提取网页正文，过滤冗余信息。|
|WebSearch|全网搜索工具，类似搜索引擎，返回搜索结果摘要及相关链接，获取实时、最新信息。|

还有包括，任务与 Agent 工具，定时任务工具，MCP 管理工具等等。

这么多工具在塞给大模型后，大模型告诉我们需要调用哪些工具，那么我们就需要一个框架来合理管理所有工具，且方便后续添加工具。

## 2. 工具管理框架
对于工具管理包括3块：
* 1. 给大模型看的TOOLS声明，格式之前文章说过，那么每新增一个tools，只需要在这个结构下新增说明即可；
```
TOOLS = [
    {"name": "bash", "description": "Run a shell command.",
     "input_schema": {"type": "object", "properties": {"command": {"type": "string"}}, "required": ["command"]}},
    {"name": "read_file", "description": "Read file contents.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "limit": {"type": "integer"}}, "required": ["path"]}},
    {"name": "write_file", "description": "Write content to file.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "content": {"type": "string"}}, "required": ["path", "content"]}},
    {"name": "edit_file", "description": "Replace exact text in file.",
     "input_schema": {"type": "object", "properties": {"path": {"type": "string"}, "old_text": {"type": "string"}, "new_text": {"type": "string"}}, "required": ["path", "old_text", "new_text"]}},
]
```
* 2. 工具函数具体执行调用的匹配
存在一个函数map，来匹配大模型返回工具名后具体执行哪个函数的匹配，这样新增一个工具后，只需要在这里也增加一下调用匹配即可；
像我们这个github项目，集成的工具有25+个，包括：
```
TOOL_HANDLERS = {
    "bash":             lambda **kw: run_bash(kw["command"], ...),
    "read_file":        lambda **kw: run_read(kw["path"], ...),
    "write_file":       lambda **kw: run_write(kw["path"], kw["content"]),
    "edit_file":        lambda **kw: run_edit(kw["path"], kw["old_text"], kw["new_text"]),
    "search_content":   lambda **kw: run_search(...),
    "web_fetch":        lambda **kw: run_web_fetch(...),
    "web_search":       lambda **kw: run_web_search(...),
    "TodoWrite":        lambda **kw: TODO.update(kw["items"]),
    "task":             lambda **kw: run_subagent(...),
    "load_skill":       lambda **kw: SKILLS.load(kw["name"]),
    "compress":         lambda **kw: "Compressing...",
    "background_run":   lambda **kw: BG.run(...),
    "cron_create":      lambda **kw: CRON.create(...),
    "task_create":      lambda **kw: TASK_MGR.create(...),
    "spawn_teammate":   lambda **kw: TEAM.spawn(...),
    "send_message":     lambda **kw: BUS.send(...),
    "shutdown_request": lambda **kw: handle_shutdown_request(...),
    "plan_approval":    lambda **kw: handle_plan_review(...),
    # ... 共约 25+ 个
}
```

* 3. 所有工具的具体实现
剩下的就是具体实现函数的实现了，比如说`run_bash`,`run_read`等具体函数的实现方法。这个比较固定，有参数传入，那么该怎么实现功能就怎么实现这个函数想实现的功能。

## 3.调用框架
有了工具定义，在调用框架上，则比较规范：
```
def agent_loop(messages: list):
    loopnum = 1
    while True:
        print(f"\n新的一次循环{loopnum}")
        loopnum += 1
        response = client.messages.create(
            model=MODEL, 
            system=SYSTEM,
            messages=normalize_messages(messages),
            tools=TOOLS, 
            max_tokens=8000,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":
            print(f"!!! 工具状态：{response.stop_reason}，已经结束工具调用\n\n")
            return
        results = []
        for block in response.content:
            if block.type == "tool_use":
                handler = TOOL_HANDLERS.get(block.name)
                output = handler(**block.input) if handler else f"Unknown tool: {block.name}"
                print(f"\033[33m【工具调用】> {block.name} \033[0m")
                print(output[:200])
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
        messages.append({"role": "user", "content": results})
```
比如一次loop自循环处理中，命中工具tool_use，就智能匹配工具并执行工具，将结果塞进对话记录中；直到stop_reason不再是tool_use，代表不需要调用工具了，本轮自循环ReAct结束。多工具使用的核心也就是在这里。

## 5. 其他
也许你发现，我们对每次循环的messages输入，做了一定规范化处理：normalize_messages(messages) ， 这里主要是为了避免某些时候工具返回的格式不对，比如大模型卡了，数据错误了等等，经过这个函数只是将输入messages做一些规范化处理，方便输入给大模型的标准格式数据不出错。
